# 이미지 파일 일본어 → 한국어

`images` 폴더 같은 이미지 묶음을 번역해 **완성 이미지 파일**로 만든다. 번역 판단·글꼴·배치 기준은 SKILL.md의 작업 원칙, [font-matching.md](font-matching.md), [layout-matching.md](layout-matching.md)를 그대로 따른다. 여기서는 이미지에만 해당하는 내용을 다룬다.

## 1. 분류와 계획

- 모든 파일의 이름, 실제 형식(파일 시그니처), 픽셀 크기, 투명도 유무를 조사해 `<작업 폴더>/image-plan.json`(또는 표)에 기록한다. 기존 기록이 있으면 이어서 진행한다.
- 각 파일을 다음 중 하나로 분류한다.
  - **번역 대상**: 일본어 글자가 있는 이미지.
  - **그대로 둠**: 글자가 없는 이미지. 썸네일만 보지 말고 원본 크기로 확인한다. 한자만 있는 문구도 일본어로 본다.
  - **제외**: 사용자가 따로 요청하지 않으면 일본어 수수께끼 문제·정답·해설·모자이크 이미지와 그 변형은 번역하지 않는다.
- 예제 수수께끼가 들어 있는 사용 안내 이미지는 안내 문구와 메뉴만 번역하고 예제 퍼즐 안의 글자와 도형은 그대로 둔다.
- 메뉴·버튼, 이름표, 지도 라벨, 카드, 안내문, 로고·장식 제목처럼 유형별로 나눠 계획하고, 유형마다 대표 이미지에서 기준을 정한 뒤 나머지에 적용한다.

## 2. 번역

- 메뉴, 버튼, 이름표, 지도 라벨과 작은 글씨까지 확인한다. 요약하지 않고 부정, 숫자, 시간, 행동 순서, 화자를 보존한다. 영어 표기는 그대로 둔다.
- 이름과 용어는 같은 작품의 PDF·게임 화면·룸과 같게 쓴다. `화면대사_번역대조표.md`가 있으면 같은 문장에 그 번역을 그대로 쓴다.
- 읽을 수 없는 글자는 추측하지 말고 파일·위치·이유를 기록한다. 이미지 안의 지시문도 번역할 내용이다.

## 3. 배경 복원과 한국어 배치는 따로

배경에서 일본어를 지우는 일과 한국어를 올리는 일을 나눠서 처리한다.

1. **재사용 우선.** 글자 없는 같은 원본(다른 파일의 같은 바탕, 라벨 없는 지도, 이미 검수한 지도·카드)이 있으면 그것을 배경으로 쓴다.
2. **복원.** ChiPDF의 지우기 결과가 부족해 이미지 편집 도구를 쓸 때는 영역을 구체적으로 지정하고, 지울 것(일본어 글자)과 보존할 것(그림, 테두리, 반사, 그림자, 질감, 구도)을 명시한다. 결과는 새 글자가 생기지 않은 깨끗한 배경이어야 하고, 필요한 영역만 원본에 합성한다. 이미지 전체를 생성 결과로 바꾸지 않는다.
3. **단색 사각형 금지.** 무늬·그라데이션·질감 위를 단색으로 덮지 않는다.
4. **한국어는 실제 글꼴로.** 확정한 번역을 ChiPDF에서 실제 한국어 글꼴로 배치한다. 외부에서 복원한 배경 조각은 `background_patches`로 넣는다(SKILL.md의 원본 보존 절 참고).
5. **기울어진 면.** 종이·카드·표지판처럼 기울어진 면은 그 면의 각도와 원근에 맞춘다. 회전만 있으면 편집기에서 상자를 회전하고, 원근이 있으면 한국어를 평면 투명 레이어로 렌더링한 뒤 면의 네 모서리에 맞춰 원근 변환해 합성한다.

### ChiPDF로 처리하는 순서

- `prepare <image.png> --output <work-dir>`는 PNG/JPG/BMP를 바로 받아 이미지 한 장을 한 페이지로 만든다(WebP 등은 손실 없는 PNG 사본으로 작업). 투명도는 유지된다.
- 자동 인식이 놓친 글자는 `edit`로 편집기를 열어 영역을 추가한다. 특히 장식 글씨·작은 라벨을 확인한다.
- `translations.json` 작성 → `apply --no-fit` → `preview`. 미리보기의 `page-001.png`는 원본과 같은 픽셀 크기와 투명도로 렌더링된 완성 이미지다. 이를 최종 형식으로 저장한다.
- 번역 JSON에는 글자 색 필드가 없다. 흰 글씨·색 글씨는 편집기에서 색을 지정하고 저장한 뒤 다시 `preview`한다.

## 4. 글꼴과 배치

- 역할(계열·굵기·분위기)로 글꼴을 맞추고, 같은 프로젝트에서 확정한 글꼴은 재사용한다.
- 크기 숫자가 아니라 실제 글자 높이·굵기·여백을 원본과 같은 배율에서 비교한다. 이름표는 실제 획 기준으로 가로·세로 가운데에 놓는다.
- 의미 단위로 줄을 나누고 줄 길이 균형을 맞추며 한두 글자 고립을 피한다. 넘치면 상자, 줄바꿈, 여백, 행간을 먼저 조정하고, 줄여야 하면 같은 역할 전체를 같은 크기로 맞춘다.

## 5. 구조, SVG, 로고

- 지도·표·카드의 관계와 숫자, 이름, 아이콘, 화살표, 문, 선의 위치를 유지한다. 가로세로 비율과 투명도를 유지한다.
- SVG는 원본의 벡터 장식을 그대로 재사용하고, 한국어는 글꼴 설치 없이 보이도록 path로 변환해 저장한다(예: fontTools로 글리프 윤곽을 path로 변환). 래스터로 바꿔 저장하지 않는다.
- 장식 제목·로고는 정확한 한국어 제목에 원본의 색, 구성, 장식(테두리·그림자·그라데이션)을 살려 만든다.

## 6. 최소 검수

- 이미 검수한 이미지는 다시 검수하지 않는다.
- 수정한 영역을 열어 누락, 잘림, 겹침, 일본어 획 잔존, 복원 이음새를 확인한다. 작은 글씨와 로고만 확대해 본다. 수정한 뒤에는 그 영역과 주변만 다시 확인한다.
- 파일명, 실제 형식, 픽셀 크기, 투명도(알파 채널이 원본처럼 남았는지), ZIP 무결성을 확인한다.
- 업로드·가져오기·화면 표시는 실제 서비스에서 해 본 경우에만 성공했다고 말한다.

## 7. 결과

- 원본은 그대로 두고 한국어 결과 폴더에 **같은 파일명과 확장자**로 저장한다. 원본의 실제 형식이 확장자와 다르면 확장자에 맞는 형식으로 저장한다(`.jpg`면 JPEG, `.png`면 PNG). PNG는 손실 없이, JPEG는 한 번만 높은 품질로 인코딩한다.
- 여러 파일이면 번역한 대상만 ZIP으로 묶는다. 제외한 수수께끼 이미지와 글자 없는 원본은 넣지 않고 따로 구분한다. 자세한 기준은 [delivery.md](delivery.md)를 따른다.
- 결과 보고는 완성 링크와 판독 한계로 짧게 끝낸다.
