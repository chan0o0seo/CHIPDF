# 결과 전달

사용자가 다른 전달 형식을 명시하면 그 요청을 우선한다.

## 결과 폴더와 파일명

- 원본 파일과 폴더는 수정하지 않는다. 결과는 별도의 한국어 결과 폴더(예: `<작업명>_한국어/`)에 저장한다.
- **완성 파일의 이름은 원본과 똑같이 한다.** PDF는 같은 파일명, 이미지는 같은 파일명과 확장자, 코코포리아 룸은 원래 ZIP 이름을 쓴다. 이미지의 실제 형식이 확장자와 다르면(예: 내용은 PNG인데 `.jpg`) 확장자에 맞는 형식으로 저장한다.
- 원본에 하위 폴더가 있으면 결과 폴더 안에서 같은 상대 경로를 유지한다.

## 묶음

- 완성 파일이 여러 개면 원래 이름과 상대 경로를 유지한 ZIP(예: `<작업명>_한국어.zip`)으로 묶는다. 보고서·미리보기·번역표·`.twproj`는 넣지 않는다.
- 이미지 작업의 ZIP에는 번역한 대상만 넣는다. 번역에서 제외한 이미지(수수께끼 문제·정답·해설 등)와 글자가 없어 그대로 둔 원본은 넣지 않고, 필요하면 별도로 구분해 둔다.
- 코코포리아 가져오기용 룸 ZIP은 원래 루트 구조를 유지한다. 바깥 전달용 ZIP에 함께 넣었다면 꺼내서 가져오도록 안내한다.

## 편집용 파일

- 완성본을 출력한 최종 `.twproj`, 번역표, 용어집, 검수 기록, 자산 대응표는 내부 작업 폴더에 보관하고, 사용자가 요청하면 전달한다. 요청이 있으면 `<작업명>_ChiPDF편집본.zip`으로 묶는다.
- 편집용 파일과 완성본은 같은 최종 저장 상태를 기준으로 한다. 최종 수정 후 `.twproj`를 저장하고 그 파일에서 다시 출력·검수한다.
- 개인 실행 경로·연결 설정·캐시·자동 백업은 묶음에서 제외한다. 외부 글꼴은 재배포가 허용될 때만 라이선스와 함께 포함하고, 그렇지 않으면 글꼴 이름과 공식 배포처를 안내한다.

## 확인

- 완성 파일의 이름·실제 형식·픽셀 크기·투명도(이미지), 페이지 수(PDF)를 원본과 대조한다.
- ZIP은 CRC 검사를 하고, 별도 임시 폴더에 풀어 파일 목록과 이름이 원본과 맞는지, 파일이 열리는지 확인한다.
- 업로드·가져오기·화면 표시는 실제 서비스에서 해 본 경우에만 성공했다고 말한다.

## 결과 보고

- 실제로 확인한 항목과, 판독하지 못한 원문(파일·페이지·위치·이유)·검수하지 못한 범위를 나눠 적는다.
- 마지막에 완성 파일(또는 ZIP)의 링크와 짧은 메모로 끝낸다. 선택한 주요 글꼴과 남은 서식 차이는 필요한 만큼만 적는다.
