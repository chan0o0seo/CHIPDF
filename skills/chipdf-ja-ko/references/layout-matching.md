# 한국어 글자의 실제 크기와 시각적 위치 보정

원본의 `font_size`·OCR 상자·좌표를 그대로 복사하면 한글이 작아 보이거나 가운데에서 벗어날 수 있다. 글꼴마다 실제 획 높이, 좌우 빈 공간, 기준선과 상자 내부 여백이 다르다. OCR 상자는 검출된 원문 범위이며 디자인의 정렬 기준을 보장하지 않는다. 원본과 **최종 렌더링된 글자**를 비교하여 크기와 위치를 확정한다. 이 절차는 PDF·룸 이미지에 모두 적용한다.

## 1. 원본에서 정렬 기준과 크기 목표 기록

대표 제목, 중앙 버튼/카드, 여러 줄 대사, 본문 등 역할이 다른 영역을 고른다. 이미지와 원본 crop에서 다음을 기록한다. 같은 역할에 공통 기준을 적용하되 의도적으로 다른 디자인은 구분한다.

- 디자인 기준 영역: 카드·버튼·말풍선 안쪽 또는 제목이 놓인 지면의 사용 가능한 범위. 아이콘·테두리·장식을 제외한 공간을 확인한다. 전체 이미지의 중심이 항상 글자의 중심은 아니다.
- 정렬 의도: 왼쪽/가운데/오른쪽, 한 줄의 중심/여러 줄 블록의 중심, 기준선 또는 상하 여백. 원본이 일부러 비대칭이면 그 구성을 보존한다. 모든 글자를 중앙으로 바꾸지 않는다.
- 실제 획 영역: 글자가 눈에 보이는 범위와 중심, 대표 글자 높이, 줄 시작 간격, 전체 블록의 폭·높이와 주변 여백. 상자 크기와 획 영역을 별도로 기록한다. 배경·테두리·그림이 섞인 픽셀 범위를 글자 크기로 측정하지 않는다.
- 시각적 위계: 제목/본문/주석의 상대 크기와 획 굵기·밀도. 숫자상 같은 크기보다 실제로 같은 비중으로 보이는지가 목표다.

좌표와 픽셀 측정은 원본과 번역의 같은 해상도·배율에서 수행한다. 미리보기가 원본과 크기가 다르면 변환 배율을 확인한 뒤 대응점을 맞춘다. 서로 다른 배율의 화면 캡처 수치를 직접 비교하지 않는다. `font_size`를 픽셀 높이나 인쇄 pt와 동일하게 취급하지 않는다.

## 2. 글꼴 확정 후 크기 보정

1. [font-matching.md](font-matching.md)로 실제 적용될 글꼴과 face를 먼저 확인한다. 폰트가 바뀌면 크기·중심을 다시 측정한다.
2. 대표 문장을 기준 크기로 렌더링하고 원본과 번역 crop을 동일 배율로 나란히 열어 비교한다. 글자 자체가 작은지, 굵기가 약한지, 블록의 폭만 좁은지 구분한다. 번역 글자 수가 줄었다고 원문 전체 폭을 채우도록 무조건 확대하지 않는다.
3. 한글의 실제 획 높이가 작으면 **크기를 키워도 된다**. 원본보다 큰 `font_size`를 오류로 취급하지 않는다. 같은 역할의 영역 여러 개를 비교하여 기준 크기를 정한다. 측정이 믿을 만한 단일 줄에서는 `새 크기 ≈ 현재 크기 × 목표 획 높이 / 현재 획 높이`를 첫 시도로 사용할 수 있다. 예: 현재 크기 18에서 획 높이 20px, 목표 26px라면 23.4로 시도한다. 이는 선형 근사이며 실제 렌더링으로 다시 확인한다. 문장 길이·행 수·글리프 차이가 큰 경우 전체 블록 높이 비율로 크기를 결정하지 않는다.
4. 정한 크기를 `layout.font_size`에 쓰고 `apply --no-fit`으로 적용한다. 기본 자동 맞춤은 크기를 다시 줄일 수 있으므로 보정 후 결과에 축소가 발생했는지 확인한다. 적용 JSON 값만 보고 최종 크기를 확인했다고 하지 않는다.
5. 글자가 넘치면 한국어 의미에 맞게 줄바꿈을 정리하고 주변 빈 공간 안에서 상자를 조정한다. 제목을 과하게 줄이거나 본문을 상자마다 작게 만들어 해결하지 않는다. 전체 폭·위계·그림과의 간격도 확인한다. 최종 크기는 엔진 지원 범위 안에서 선택한다.

굵기 부족을 크기 증가만으로 해결하지 않는다. 장평·자간·행간 전용 필드는 현재 JSON에서 지원되지 않으므로 만들어 넣지 않는다. 해당 조정이 필요하면 ChiPDF 편집기의 실제 지원 기능으로 마무리하고 렌더링을 다시 확인한다.

## 3. 가운데 치우침과 상하 위치 보정

중앙 정렬에는 상자의 중심과 **보이는 글자 블록의 중심**이라는 두 단계가 있다. `align: "center"`는 번역 상자 안에서의 가로 정렬이며 카드 전체의 중앙 배치나 세로 정렬을 보장하지 않는다.

1. `layout.rect`를 검출된 일본어 획의 좁은 OCR 상자로 고정하지 않는다. 원본 디자인의 안전한 기준 영역에 맞춰 폭과 x를 정하고 `align: "center"`를 사용한다. 예를 들어 기준 영역의 중심이 `cx`이고 번역 상자 폭이 `w`라면 `x = cx - w/2`가 첫 위치다. 아이콘이 있는 버튼은 아이콘을 제외한 텍스트 자리의 기준을 사용한다.
2. 렌더링 후 실제 한국어 획 영역을 확인한다. 글자 중심이 기준보다 왼쪽이면 `dx = 목표 중심 x - 렌더링된 획 중심 x`를 참고해 번역 상자 x를 옮긴다. 상하 위치도 `dy = 목표 중심 y - 렌더링된 획 중심 y`를 참고해 y를 조정한다. 배율과 좌표 원점이 같은 경우에만 이 차이를 사용한다. **상자 높이의 절반을 빼는 것만으로 세로 중앙 정렬됐다고 판단하지 않는다.**
3. 한 줄은 해당 줄의 획 높이·기준선·상하 여백을 비교하고, 여러 줄은 전체 블록의 중심과 각 줄의 정렬을 함께 확인한다. 세로 가운데 정렬이 필요한 영역에서는 블록 전체가 맞도록 y를 조정한다. 원본이 위쪽 정렬인 본문을 세로 가운데로 바꾸지 않는다.
4. 숫자나 문장부호, 열린 획, 굵은 글자가 한쪽에 몰린 경우 기하학적 가운데라도 시각적으로 치우칠 수 있다. 측정으로 큰 오차를 먼저 없애고, 같은 배율의 원본/번역을 번갈아 보며 작은 이동을 조정한다. 이동 방향과 이유를 기록한다. 밝기 중심이나 글자 개수만으로 광학적 중심을 자동 확정하지 않는다.
5. 크기·줄바꿈·상자 폭이 바뀌면 중심과 상하 여백도 다시 확인한다. 위치와 크기를 한 번에 무작정 바꾸지 말고 **폰트 → 크기/줄바꿈 → 상자 정렬 → 실제 획 중심 보정 → 전체 지면 확인** 순서로 조정한다.

번역 상자의 이동·확대는 원문 지우기 영역과 분리한다. 지우기 영역을 번역 상자에 맞춰 옮기면 일본어가 남거나 그림이 지워질 수 있다. `layout.rect`는 번역 상자만 바꾸며 원문 지우기 영역은 유지한다. 지우기 불량은 별도로 원본과 비교해 수정한다.

## 4. 비교 기록과 완료 판단

`<work-dir>/layout-review.json` 또는 서식 메모에 항목 ID/룸 자산명, 역할, 디자인 기준 영역, 목표 정렬, 변경 전후 크기·rect, 비교 이미지 경로와 남은 차이를 기록한다. 이 기록에 적은 `source_ink_rect`, `target_ink_rect`, `anchor` 등의 측정 필드를 translations JSON의 `layout`에 추가하지 않는다. 실제 적용 필드는 `font_family`, `font_size`, `align`, `writing_mode`, `rect`뿐이다.

- 비교 이미지는 동일 크기의 원본/번역 crop을 나란히 배치한다. 필요하면 별도 검수 이미지에 기준선·중심선·획 영역을 표시하거나 반투명 비교본을 만든다. 선과 표시를 최종 자산에 넣지 않는다. 이미지 도구로 측정할 때는 배경과 문자 획을 제대로 구분했는지 원본을 직접 확인한다.
- 역할별 대표 영역에서 기준을 확정한 후 모든 번역 영역에 적용하고 검토한다. 대표 영역만 고쳤다고 나머지 영역을 완료 처리하지 않는다. 제목·중앙 버튼·카드·말풍선과 자동 축소된 상자는 우선 확인한다.
- 실제 읽는 크기에서 중앙 제목/버튼의 치우침이 보이지 않고, 글자의 비중·제목 위계·본문 가독성이 원본과 어울려야 한다. 확대 보기에서 잘림·겹침·과도한 여백과 기준선 어긋남을 확인한다. 그림과 원래 의도된 비대칭을 보존한다.
- 원본의 숫자와 다른 크기를 선택했어도 외형·가독성이 맞으면 유지한다. 자동 검사 0건이나 `align: center` 설정만으로 정렬/크기 검수를 완료하지 않는다. 눈에 띄는 오차가 남으면 수정하여 다시 렌더링하거나 구체적 미완료로 남긴다.
- PDF 출력과 룸 이미지 재인코딩·리사이즈 후 **최종 파일**을 다시 연다. 룸 자산은 픽셀 크기·투명도·룸에서 쓰이는 표시 크기도 확인하고, 변경된 바이트에 맞춰 해시 파일명과 참조를 갱신한다. PNG 미리보기에서만 맞는 상태를 최종 완료로 보고하지 않는다.
