# 코코포리아 룸 ZIP 일본어 → 한국어

룸 번역은 JSON의 표시 문구와 이미지에 그려진 글자를 함께 다루는 작업이다. ChiPDF는 이미지 문구 편집에 사용하고, ZIP/JSON 재구성은 별도 파일 작업으로 수행한다. ChiPDF 런처에 room 서브명령이 있다고 가정하지 않는다. 사용자가 룸을 요청했으면 가져오기용 ZIP을 결과로 제공한다. PDF만 번역해 룸 번역을 완료했다고 보고하지 않는다.

## 확인한 형식과 도구

로컬 샘플에서 관찰한 형식은 `meta.version: "1.1.0"`, `__data.json`, `.token`, SHA256 기반 파일명의 이미지 자산이다. JSON에는 `meta`, `entities`, `resources`가 있고, `entities`에는 `room`, `items`, `decks`, `notes`, `characters`, `effects`, `scenes`, `savedatas`, `snapshots`가 있다. 실제 항목은 ID를 키로 가진 객체 또는 다른 구조일 수 있다. 이 내용은 관찰한 프로필이며 공식 고정 JSON 스키마가 아니다. 버전이나 구조가 다르면 원본을 먼저 조사하고 검사·패키징 로직을 맞춘다.

`python <skill-dir>/scripts/ccfolia_room.py inspect <room.zip> --output <work-dir>/room-inventory.json`으로 추출 없이 ZIP의 구조, 자산, 모든 entities 문자열과 JSON Pointer 경로를 조사한다. 표준 라이브러리만 사용하므로 ChiPDF 연결 없이 실행할 수 있다. `inspect`는 알려진 프로필의 오류를 보고서에 남겨도 조사 자체는 성공할 수 있다. 출력의 `errors`와 `warnings`를 읽는다. `validate`는 오류가 있으면 종료 코드 1을 반환한다.

공식 사용 안내: [CCFOLIA 룸 데이터](https://docs.ccfolia.com/gm-only/room-option/room-settings/room-data). ZIP은 룸 데이터 가져오기 또는 보드로 드래그하여 불러올 수 있다. 공식 안내상 오디오 파일은 내보내기에 포함되지 않는다. 온라인 가져오기 방식·제한이 작업에 중요하면 공식 페이지를 다시 확인한다.

## 1. 작업 범위와 원본 조사

- 입력 ZIP과 시나리오의 확정 번역·용어집을 읽고 새 작업 폴더에 원본 SHA256과 조사 보고서를 남긴다. 원본 ZIP을 덮어쓰지 않는다. 룸만 요청됐으면 관련 없는 시나리오 PDF 전체 번역으로 범위를 확장하지 않는다.
- ZIP 내부 경로를 확인하고 필요한 파일만 작업 폴더 안으로 안전하게 추출한다. 절대 경로, `..`, 중복 멤버를 거절하고 무조건 `extractall`하지 않는다. 원본의 루트 배치와 내부 경로를 기록한다.
- 자산 목록을 썸네일/contact sheet로 보고 일본어가 있는 핸드아웃·카드·설명 패널·버튼·배경을 구분한다. 글자 없는 삽화·장식과 오디오 등은 그대로 보존한다. OCR 결과나 파일명만으로 글자 유무를 판단하지 않는다. 한자만 있는 문구도 검토한다.
- 문자열 목록의 category는 검토 단서다. `display_text_candidate`라도 식별자 참조가 섞일 수 있고 `other_string_review`에도 표시 문구가 있을 수 있다. `has_kana`가 false여도 일본어가 없다는 뜻이 아니다. ID별로 중복 이미지가 사용되는 모든 위치와 장면/저장 데이터의 사본을 기록한다.

## 2. JSON 문구 번역과 동작 보존

번역표 `<work-dir>/room-translations.json`은 룸용 작업 기록이다. PDF용 `translations.json` 스키마와 혼용하지 않는다. 항목에는 `path`, `source`, `source_sha256`, `target`, `decision`(translate/preserve), 필요하면 설명을 기록한다. JSON Pointer의 `~1`은 `/`, `~0`은 `~`로 복원한다. 적용 시 현재 원문과 해시가 일치하는지 확인하고 검토한 경로의 문자열 값만 바꾼다.

| 대상 | 처리 |
| --- | --- |
| 패널/카드 메모, 설명, 공유 메모, 핸드아웃, 화면 안내, 장면 표시명 | 실제 표시 용도와 문맥을 확인해 번역 |
| 캐릭터 이름·소개, 표시 라벨 | 확정 용어에 맞춰 번역. 라벨이 수식 변수로 쓰이면 참조까지 추적 |
| 채팅 팔레트·버튼 clickAction·명령이 섞인 text | 명령 문법과 사람이 읽는 문구를 분리. 단순 일괄 번역 금지 |
| ID, 객체 키, URL, 파일명, 주사위 수식, 변수 참조, 색상·숫자·플래그·좌표·권한 | 보존. 자산 교체나 명칭 변경으로 연결된 참조를 갱신해야 할 때만 별도 기록 |

실제 샘플에서는 장면 이름 `ゲーム画面`과 버튼 명령 `/scene ゲーム画面`이 연결된다. 이름을 `게임 화면`으로 바꾸면 해당 장면을 가리키는 명령의 인수도 갱신한다. `/scene` 자체는 유지한다. 장면·저장 데이터 안의 버튼 사본도 확인한다. 이 대응은 확인한 예시이며 모든 `/` 문자열의 문법을 추측해 치환하지 않는다. 모르는 명령은 공식 설명이나 실제 앱 동작으로 확인한다.

`{변수}`, 주사위 식, `//` 변수 정의, 선택지 구분, 줄바꿈, 서식 기호를 포함한 문자열은 구문을 보존한다. 표시 라벨·변수명·장면명을 변경할 때는 이름 대응표와 모든 사용처를 확인한다. 지원을 확신할 수 없는 동작 관련 명칭은 보존하고 이유를 기록한다. GM용 정보의 공개/비공개 상태를 유지한다.

## 3. 이미지 문구 번역과 폰트 매칭

전체 자산을 일괄 적용하기 전에 SKILL.md의 서식 단계를 수행한다. 실제 웹 검색·공식 후보 열람, 대표 카드/버튼/제목의 한국어 미리보기 비교, 크기·위치 보정과 근거 기록을 포함한다. `font-candidates.json`과 `layout-review.json` 없이 설치 폰트를 바로 지정한 것을 검수된 폰트·레이아웃 선정으로 취급하지 않는다. 같은 프로젝트에서 검수한 기록은 재사용 가능하다.
- 자산별 원본 경로·SHA256·픽셀 크기·형식·투명도·사용처와 translate/preserve 결정을 `<work-dir>/asset-map.json`에 기록한다. 같은 파일의 반복 참조는 한 번 번역하여 재사용한다. 서로 다른 파일의 문구가 같아도 외형을 확인하기 전에는 합치지 않는다.
- 원본 문구와 시나리오의 확정 번역을 대조한다. ChiPDF가 직접 받는 입력은 PDF 또는 `.twproj`이므로 이미지가 바로 입력된다고 가정하지 않는다. 원본과 대응되는 PDF가 있으면 같은 그림·크기인지 확인하고 사용한다. 그렇지 않으면 필요한 이미지들을 크기·배율과 페이지↔자산 대응표를 유지하여 작업용 PDF로 만든다. 서로 다른 크기를 같은 규격으로 늘이거나 자르지 않는다.
- ChiPDF의 prepare → 문맥 번역 → apply → preview 흐름을 사용하고 [font-matching.md](font-matching.md)에 따라 제목·본문·대사별 가까운 한국어 폰트를 선택한다. 전체 이미지와 작은 글자 crop을 모두 열어 누락·배경 복원·서식·가독성을 확인한다.
- [layout-matching.md](layout-matching.md)로 카드·버튼·제목의 디자인 중심과 실제 한국어 획 중심을 비교하고, 같은 숫자의 크기에서 작아 보이면 확대한다. 크기 확정 후 `--no-fit`으로 적용하고 위치를 보정한다. 특히 한글이 왼쪽에 치우쳤거나 상하 여백이 달라진 이미지는 다시 렌더링해 확인한다. 카드 테두리·아이콘을 포함한 전체 그림의 중심을 텍스트 중심으로 가정하지 않는다.
- 룸에 돌려 넣는 결과는 해당 자산의 이미지다. 페이지 번호나 PDF 여백이 들어간 화면 캡처를 자산으로 쓰지 않는다. 대응표를 기준으로 픽셀 크기·가로세로비를 복원하고 실제 포맷과 확장자·MIME을 일치시킨다. 원본의 투명도·장식·그림을 보존한다. 작업용 PDF가 알파를 평탄화했다면 원본 알파를 무조건 덮어씌우지 말고 번역 글자 및 지우기 영역까지 포함한 합성을 검증한다. 투명 자산을 제대로 복원할 수 없으면 미완료로 기록한다.
- 번역한 모든 자산을 실제로 열어 확인한 뒤 이미지 교체표를 확정한다. PNG는 가능한 경우 손실 없이, JPEG는 불필요한 반복 인코딩을 피한다. 원본과 번역 이미지의 바이트를 보관하고 사용자가 편집 중인 `.twproj`에는 자동 적용하지 않는다.

## 4. 이미지 참조와 ZIP 재구성

관찰한 프로필의 자산명은 `<이미지 최종 바이트 SHA256>.<확장자>`다. 이미지를 번역하면 이전 파일명 아래 바이트만 교체하지 말고 최종 인코딩 바이트의 SHA256으로 이름을 만든다. 최종 이미지의 `old_name → new_name` 대응표를 먼저 고정한다.

1. `resources`의 키를 새 이름으로 갱신하고 그 값의 메타데이터를 보존한다. 형식이 바뀐 경우에는 실제 MIME 등 확인된 관련 항목만 갱신한다. 동일 새 이름으로 합쳐지는 경우 바이트·메타데이터 충돌을 확인한다.
2. JSON 전체를 재귀 순회하여 이전 자산명을 **정확하게 값으로 가진 문자열**을 새 이름으로 바꾼다. room, 패널, 카드/덱, 장면, 저장 데이터, 스냅샷 등 모든 참조를 확인한다. JSON 원문에 부분 문자열 치환을 하지 않는다. 외부 URL이나 복합 경로에 자산명이 들어 있으면 실제 형식을 확인하고 개별 처리한다.
3. 새 이름의 이미지 파일을 넣고 더 이상 쓰지 않는 교체 전 자산만 제외한다. 교체하지 않은 멤버의 바이트는 그대로 보존한다. 원본의 기타 멤버를 임의로 삭제하지 않는다.
4. `__data.json`을 UTF-8로 직렬화한 **최종 바이트**를 고정한다. 관찰한 `.token` 형식은 `0.<__data.json 최종 바이트의 SHA256>`이며 해당 형식일 때만 같은 방식으로 재생성한다. 토큰 생성 후 JSON을 다시 포맷하면 체크섬이 달라진다. 토큰이 다르면 추측해 고치지 말고 형식을 조사한다.
5. 내부 파일을 원본과 같은 루트 구조의 새 ZIP으로 만든다. 상위 작업 폴더를 한 겹 추가하지 않는다. 검사 보고서·번역표·ChiPDF 프로젝트는 룸 ZIP 밖에 보관한다. 완성 ZIP을 다시 열어 아래 검사를 실행한다.

## 5. 검증과 가져오기 확인

`python <skill-dir>/scripts/ccfolia_room.py validate <korean-room.zip> --original <room.zip> --output <work-dir>/room-validation.json`

도구는 ZIP CRC, 중복/위험 경로, 알려진 버전·구조, `.token` 체크섬, resources의 파일 존재, 해시 파일명과 바이트, 확인 가능한 로컬 참조를 검사한다. JSON 구조 차이와 자산 변경 목록도 남긴다. 오류 0은 번역·모든 참조·온라인 가져오기 성공을 보장하지 않는다. 다른 버전과 비표준 경로에는 미검증 경고/오류가 나며 실제 구조를 조사한다.

추가로 다음을 직접 확인한다.

- `json_changes`의 변경이 검토한 문구·명칭 참조·자산 참조/메타데이터에 한정되는지 대조한다. ID·좌표·크기·레이어·순서·잠금·표시/비밀·주사위 설정·오디오 참조 등이 뜻하지 않게 바뀌지 않았는지 확인한다. 도구의 `structural_diff_reviewed: false`는 에이전트가 변경 내용을 검토해야 한다는 표시다.
- 자산 교체표와 변경 목록을 대조하고 미번역 자산의 SHA256이 유지되는지 확인한다. 모든 이미지가 디코딩되는지 별도 이미지 도구로 검사하고 크기·투명도도 대조한다. `image_decode_tested`는 이 스크립트가 검사하지 않았으므로 false다.
- 모든 표시 문구 및 모든 번역 이미지의 원문을 대조한다. 남은 일본어 후보에는 의도적 보존/미완료 사유를 남긴다. 가나 검색 0건이나 OCR 문제 0건을 완역 근거로 삼지 않는다.
- 실제 가져오기 검증은 사용자가 요청하거나 이미 허용한 경우 새 테스트 룸에서 수행한다. 활성 플레이 룸에 시험으로 덮어쓰지 않는다. 보드·모든 장면 전환·카드 앞/뒷면·덱·공유 메모·버튼·캐릭터·팔레트와 GM 비밀 상태를 확인한다. 오디오 원본 누락은 별도 설정 문제로 보고하며 임의 음원을 추가하지 않는다. 룸의 클릭 동작 중 채팅 발송 등이 포함되면 별도 권한 없이 실행하지 않는다.

검사 도구는 항상 `actual_ccfolia_import_tested: false`로 기록한다. 실제 가져오기를 별도로 수행한 경우 테스트 룸과 확인한 기능을 별도 검수 기록에 남긴다. 온라인 검증을 하지 않았다면 결과 전달에 **파일 검사 완료, 실제 코코포리아 가져오기 미확인**을 명시한다.

## 결과 전달

가져오기용 한국어 ZIP을 절대 경로로 전달하고 주요 용어·폰트와 구체적인 미완료 항목을 간단히 적는다. 사용자가 후속 편집을 원하면 이미지용 `.twproj`와 자산 대응표도 함께 전달한다. 보고서에는 문구/이미지 처리 개수, 구조·해시 검사 결과와 실제 가져오기 여부를 구분한다. 원본 그림만 있는 자산과 의도적으로 보존한 코드·고유명사가 남아 있다는 이유로 무조건 미완성으로 판정하지 않는다.
