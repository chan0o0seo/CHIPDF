# 코코포리아 룸 ZIP 일본어 → 한국어

룸 번역은 JSON의 표시 문구와 이미지에 그려진 글자를 함께 다루는 작업이다. ChiPDF는 이미지 문구 편집에 사용하고, ZIP/JSON 조사·재구성·검사는 `scripts/ccfolia_room.py`로 한다. ChiPDF 런처에 room 서브명령이 있다고 가정하지 않는다. 사용자가 룸을 요청했으면 가져오기용 ZIP을 결과로 제공한다. PDF만 번역해 룸 번역을 완료했다고 보고하지 않는다.

## 확인한 형식과 도구

로컬 샘플에서 관찰한 형식은 `meta.version: "1.1.0"`, `__data.json`, `.token`, SHA256 기반 파일명의 이미지 자산이다. JSON에는 `meta`, `entities`, `resources`가 있고, `entities`에는 `room`, `items`, `decks`, `notes`, `characters`, `effects`, `scenes`, `savedatas`, `snapshots`가 있다. 실제 항목은 ID를 키로 가진 객체 또는 다른 구조일 수 있다. 이 내용은 관찰한 프로필이며 공식 고정 JSON 스키마가 아니다. 버전이나 구조가 다르면 원본을 먼저 조사하고 검사·패키징 로직을 맞춘다.

`python <skill-dir>/scripts/ccfolia_room.py inspect <room.zip> --output <work-dir>/room-inventory.json --template <work-dir>/room-translations.json`으로 추출 없이 ZIP의 구조, 자산, 모든 entities 문자열과 JSON Pointer 경로를 조사하고, 일본어가 들어 있는 문자열의 번역표 초안을 만든다. 번역표가 이미 있으면 덮어쓰지 않는다. 표준 라이브러리만 사용하므로 ChiPDF 연결 없이 실행할 수 있다. `inspect`는 알려진 프로필의 오류를 보고서에 남겨도 조사 자체는 성공할 수 있다. 출력의 `errors`와 `warnings`를 읽는다. `validate`는 오류가 있으면 종료 코드 1을 반환한다.

공식 사용 안내: [CCFOLIA 룸 데이터](https://docs.ccfolia.com/gm-only/room-option/room-settings/room-data). ZIP은 룸 데이터 가져오기 또는 보드로 드래그하여 불러올 수 있다. 공식 안내상 오디오 파일은 내보내기에 포함되지 않는다. 온라인 가져오기 방식·제한이 작업에 중요하면 공식 페이지를 다시 확인한다.

## 1. 작업 범위와 원본 조사

- 입력 ZIP과 시나리오의 확정 번역·용어집, `화면대사_번역대조표.md`(있으면)를 읽고 새 작업 폴더에 원본 SHA256과 조사 보고서를 남긴다. 원본 ZIP을 덮어쓰지 않는다. 룸만 요청됐으면 관련 없는 시나리오 PDF 전체 번역으로 범위를 확장하지 않는다.
- ZIP 내부 경로를 확인하고 필요한 파일만 작업 폴더 안으로 안전하게 추출한다. 절대 경로, `..`, 중복 멤버를 거절하고 무조건 `extractall`하지 않는다. 원본의 루트 배치와 내부 경로를 기록한다.
- 자산 목록을 썸네일/contact sheet로 보고 일본어가 있는 핸드아웃·카드·설명 패널·버튼·배경을 구분한다. 글자 없는 삽화·장식과 오디오 등은 그대로 보존한다. OCR 결과나 파일명만으로 글자 유무를 판단하지 않는다. 한자만 있는 문구도 검토한다.
- 문자열 목록의 category는 검토 단서다. `display_text_candidate`라도 식별자 참조가 섞일 수 있고 `other_string_review`에도 표시 문구가 있을 수 있다. `has_kana`가 false여도 일본어가 없다는 뜻이 아니다. ID별로 중복 이미지가 사용되는 모든 위치와 장면/저장 데이터의 사본을 기록한다.

## 2. JSON 문구 번역과 동작 보존

번역표 `<work-dir>/room-translations.json`은 룸용 작업 기록이다. PDF용 `translations.json` 스키마와 혼용하지 않는다. 각 항목의 `path`, `source`, `source_sha256`는 그대로 두고 `decision`을 `translate` 또는 `preserve`로 정한 뒤 `translate`면 `target`을 쓴다. 필요하면 `note`에 이유를 적는다. 정하지 않았거나 `target`이 빈 항목이 있으면 `build`가 멈춘다. `build`는 현재 원문과 해시가 일치하는 경로의 문자열 값만 바꾼다. 초안은 일본어가 있는 문자열만 담으므로, 한국어로 바꿔야 할 다른 문자열이 있으면 인벤토리의 경로·해시로 항목을 추가한다.

| 대상 | 처리 |
| --- | --- |
| 패널/카드 메모, 설명, 공유 메모, 핸드아웃, 화면 안내, 장면 표시명 | 실제 표시 용도와 문맥을 확인해 번역 |
| 캐릭터 이름·소개, 표시 라벨 | 확정 용어에 맞춰 번역. 라벨이 수식 변수로 쓰이면 참조까지 추적 |
| 채팅 팔레트·버튼 clickAction·명령이 섞인 text | 명령 문법과 사람이 읽는 문구를 분리. 단순 일괄 번역 금지 |
| ID, 객체 키, URL, 파일명, 주사위 수식, 변수 참조, 색상·숫자·플래그·좌표·권한 | 보존. 자산 교체나 명칭 변경으로 연결된 참조를 갱신해야 할 때만 별도 기록 |

실제 샘플에서는 장면 이름 `ゲーム画面`과 버튼 명령 `/scene ゲーム画面`이 연결된다. 이름을 `게임 화면`으로 바꾸면 해당 장면을 가리키는 명령의 인수도 갱신한다. `/scene` 자체는 유지한다. 장면·저장 데이터 안의 버튼 사본도 확인한다. `build`는 장면 이름을 바꿨는데 `/scene` 명령이 옛 이름을 그대로 쓰면 멈춘다. 이 대응은 확인한 예시이며 모든 `/` 문자열의 문법을 추측해 치환하지 않는다. 모르는 명령은 공식 설명이나 실제 앱 동작으로 확인한다.

`{변수}`, 주사위 식, `//` 변수 정의, 선택지 구분, 줄바꿈, 서식 기호를 포함한 문자열은 구문을 보존한다. 표시 라벨·변수명·장면명을 변경할 때는 이름 대응표와 모든 사용처를 확인한다. 지원을 확신할 수 없는 동작 관련 명칭은 보존하고 이유를 기록한다. GM용 정보의 공개/비공개 상태를 유지한다.

## 3. 이미지 문구 번역과 폰트 매칭

이미지 작업은 [image-localization.md](image-localization.md)의 분류·번역·배경 복원·글꼴·검수 기준을 그대로 따른다. 수수께끼 문제·정답·해설 이미지 제외, 예제 퍼즐 보존, 단색 사각형 금지, 기울어진 면의 원근 맞춤도 같다. 룸에만 해당하는 점은 다음과 같다.

- 자산별 원본 이름·SHA256·픽셀 크기·형식·투명도·사용처와 translate/preserve/exclude 결정을 `<work-dir>/asset-map.json`에 기록한다. 같은 파일의 반복 참조는 한 번 번역해 재사용한다. 서로 다른 파일의 문구가 같아도 외형을 확인하기 전에는 합치지 않는다.
- 전체 자산에 적용하기 전에 SKILL.md의 서식 단계(글꼴 후보 비교, 대표 카드·버튼·제목의 크기·위치 보정, `font-candidates.json`·`layout-review.json` 기록)를 수행한다. 같은 프로젝트에서 검수한 기록은 재사용한다.
- 자산 이미지는 ChiPDF `prepare`에 바로 넣는다(PNG/JPG/BMP, 투명도 유지). 작업용 PDF로 바꾸거나 크기를 늘이거나 자르지 않는다. 번역 후 `apply --no-fit` → `preview`의 `page-001.png`가 원본과 같은 픽셀 크기·투명도의 결과 이미지다. 페이지 번호나 여백이 들어간 화면 캡처를 자산으로 쓰지 않는다.
- 결과 이미지는 원본 자산과 같은 형식으로 저장한다(`.png`면 PNG, `.jpg`면 JPEG). 투명도가 원본처럼 남았는지, 번역 글자와 지운 영역 밖의 알파가 그대로인지 확인한다. 투명 자산을 제대로 복원할 수 없으면 미완료로 기록한다.
- 번역한 자산을 모두 열어 확인한 뒤 자산 교체표를 확정한다. 사용자가 편집 중인 `.twproj`에는 자동 적용하지 않는다.

## 4. 룸 ZIP 다시 만들기

문구 번역표와 자산 교체표를 확정하면 도구로 새 룸 ZIP을 만든다. 자산 교체표 형식은 `{"replacements": [{"name": "<원래 자산 파일명>", "file": "<번역한 이미지 경로>"}]}`이며 상대 경로는 교체표 파일 위치 기준이다.

`python <skill-dir>/scripts/ccfolia_room.py build <room.zip> --translations <work-dir>/room-translations.json --assets <work-dir>/asset-replacements.json --output <결과 폴더>/<원래 룸 ZIP 이름> --report <work-dir>/room-build.json`

도구가 하는 일:

1. 번역표의 `translate` 항목을 원문 해시가 일치할 때만 적용한다. 정하지 않은 항목이 있거나, 장면 이름을 바꿨는데 `/scene` 명령이 옛 이름을 쓰면 멈춘다(`--allow-incomplete`는 사용자가 초안을 요청했을 때만).
2. 번역 이미지가 원래 확장자의 실제 형식인지 확인하고, 최종 바이트의 SHA256으로 새 파일명을 만든다. `resources` 키를 바꾸고 메타데이터는 유지한다.
3. JSON 전체에서 옛 자산명을 **정확히 값으로 가진 문자열**만 새 이름으로 바꾼다. 옛 이름이 더 긴 문자열 안에 남아 있으면 멈추므로 그 경로를 직접 확인한다.
4. 원본과 같은 압축 JSON으로 `__data.json`을 쓰고 `.token`을 `0.<SHA256>`으로 다시 만든다. 원본의 멤버 순서·압축 방식·루트 구조를 유지하고, 교체하지 않은 파일의 바이트는 그대로 둔다. 원본 ZIP은 수정하지 않는다.
5. 완성 ZIP을 다시 열어 검사하고 보고서에 남은 일본어 문자열(`japanese_strings_remaining`), 자산 이름 변경, JSON 변경 목록을 기록한다.

도구가 처리하지 못하는 비표준 구조나 다른 버전은 원본을 조사한 뒤 같은 원칙으로 수동 처리한다. 검사 보고서·번역표·ChiPDF 프로젝트는 룸 ZIP 밖에 보관한다.

## 5. 검증과 가져오기 확인

`python <skill-dir>/scripts/ccfolia_room.py validate <korean-room.zip> --original <room.zip> --output <work-dir>/room-validation.json`

도구는 ZIP CRC, 중복/위험 경로, 알려진 버전·구조, `.token` 체크섬, resources의 파일 존재, 해시 파일명과 바이트, 확인 가능한 로컬 참조를 검사한다. JSON 구조 차이와 자산 변경 목록도 남긴다. 오류 0은 번역·모든 참조·온라인 가져오기 성공을 보장하지 않는다. 다른 버전과 비표준 경로에는 미검증 경고/오류가 나며 실제 구조를 조사한다.

추가로 다음을 직접 확인한다.

- `json_changes`의 변경이 검토한 문구·명칭 참조·자산 참조/메타데이터에 한정되는지 대조한다. ID·좌표·크기·레이어·순서·잠금·표시/비밀·주사위 설정·오디오 참조 등이 뜻하지 않게 바뀌지 않았는지 확인한다. 도구의 `structural_diff_reviewed: false`는 에이전트가 변경 내용을 검토해야 한다는 표시다.
- 자산 교체표와 변경 목록을 대조하고 미번역 자산의 SHA256이 유지되는지 확인한다. 모든 이미지가 디코딩되는지 별도 이미지 도구로 검사하고 크기·투명도도 대조한다. `image_decode_tested`는 이 스크립트가 검사하지 않았으므로 false다.
- 모든 표시 문구 및 모든 번역 이미지의 원문을 대조한다. 남은 일본어 후보에는 의도적 보존/미완료 사유를 남긴다. 가나 검색 0건이나 OCR 문제 0건을 완역 근거로 삼지 않는다.
- 실제 가져오기 검증은 사용자가 요청하거나 이미 허용한 경우 새 테스트 룸에서 수행한다. 활성 플레이 룸에 시험으로 덮어쓰지 않는다. 보드·모든 장면 전환·카드 앞/뒷면·덱·공유 메모·버튼·캐릭터·팔레트와 GM 비밀 상태를 확인한다. 오디오 원본 누락은 별도 설정 문제로 보고하며 임의 음원을 추가하지 않는다. 룸의 클릭 동작 중 채팅 발송 등이 포함되면 별도 권한 없이 실행하지 않는다.

검사 도구는 항상 `actual_ccfolia_import_tested: false`로 기록한다. 실제 가져오기를 별도로 수행한 경우 테스트 룸과 확인한 기능을 별도 검수 기록에 남긴다. 온라인 검증을 하지 않았다면 결과 전달에 **파일 검사 완료, 실제 코코포리아 가져오기 미확인**을 명시한다.

## 결과 전달

[delivery.md](delivery.md)를 따른다. 한국어 룸 ZIP은 한국어 결과 폴더에 **원래 룸 ZIP과 같은 이름**으로 저장하고 원래 루트 구조를 유지한다. 이미지용 최종 `.twproj`·자산 대응표·번역표·검수 기록은 내부 작업 폴더에 보관하고 요청하면 전달한다. 보고서에는 문구/이미지 처리 개수, 구조·해시 검사 결과와 실제 가져오기 여부를 구분하고, 판독하지 못한 원문과 미완료 항목을 따로 적는다. 원본 그림만 있는 자산과 의도적으로 보존한 코드·고유명사가 남아 있다는 이유로 무조건 미완성으로 판정하지 않는다. 실제 가져오기를 하지 않았다면 **파일 검사 완료, 실제 코코포리아 가져오기 미확인**이라고 적는다.
