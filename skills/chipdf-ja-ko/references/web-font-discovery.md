# 인터넷에서 한국어 폰트 탐색·비교·적용

사용자가 인터넷 검색·비교를 요청했거나 로컬 후보가 부족하면 이 흐름을 수행한다. 이 사용자는 설치된 폰트가 적어 웹 탐색과 비교를 원하므로, 원본과 가까운 폰트를 고르는 작업에 로컬 목록만으로 결론 내리지 말고 웹 후보도 검토한다. 이미 해당 프로젝트에서 원본과 비교해 확정한 폰트가 있으면 재사용하며 매번 다시 검색할 필요는 없다. 사용자가 폰트를 지정하면 그 선택을 우선한다.

## 검색과 후보 축소

**새 프로젝트의 폰트 선정에서 실제 검색과 열람을 생략하지 않는다.** 이미 설치된 폰트가 많거나 Noto가 있다는 사실은 웹 비교의 대체 근거가 아니다. 알려진 공식 URL을 `official_candidates`에 적는 것, 검색 결과 제목만 보는 것, 이 참고 문서를 읽는 것은 공식 샘플을 열어 비교한 것과 다르다. 같은 프로젝트에서 검수한 선택을 재사용할 때만 기존 근거와 재사용 이유를 남겨 중복 검색을 생략할 수 있다. 검색 도구나 페이지가 차단되면 도구 결과와 미수행 범위를 기록한다.

1. 원본 대표 영역의 명조/고딕/둥근 고딕/손글씨/붓글씨/장식 계열, 굵기, 자폭, 획 대비, 시대감과 역할을 기록한다. 제목·본문·대사는 다른 후보를 쓸 수 있다.
2. 웹 검색 도구로 `한국어 명조 폰트 강한 획 대비`, `한글 둥근 고딕 폰트`, `한글 붓글씨 폰트` 등 원본 특성에 맞는 검색어를 사용한다. 아래 배포처를 시작점으로 사용하되 예시 폰트만으로 후보를 제한하지 않는다. 이름이 비슷하거나 인기 있는 폰트라는 이유만으로 선택하지 않는다.
3. 공식 배포 페이지의 샘플 이미지·글꼴 보기·패밀리 설명을 실제로 확인하여 역할별 2~3개 후보를 좁힌다. 다른 문자 체계나 일본어 전용 버전을 한글 지원 폰트로 착각하지 않는다. 웹 샘플에서는 실제 한국어 글자와 해당 굵기를 확인한다.
4. 비교표에 후보 family, 공식 배포 페이지, 라이선스 페이지, 굵기/형식, 원본과 닮은 점·다른 점, 다운로드 및 렌더링 여부를 기록한다. 검색 결과의 설명만 읽었으면 외형 비교 완료로 표시하지 않는다. 사이트에 사용자 문장을 입력할 수 있어도 시나리오 원문·미공개 번역을 전송하지 말고 공개된 일반 문장으로 살펴본다. 실제 시나리오 문장 비교는 로컬에서 수행한다.

`font-candidates.json`의 각 후보는 `search_query`, `opened_page`, `checked_date`, `family`, `preview_path`, `comparison_observation`, `decision`을 기록한다. 다운로드하지 않은 후보는 `preview_path`를 비워 두고 `decision`에 웹 샘플만 비교했는지/탈락했는지 적는다. 최종 선정 후보의 실제 번역문 렌더링이 없으면 적용 검증 완료로 기록하지 않는다. 이 항목들은 작업 기록이며 번역 JSON의 필드가 아니다. 실제 도구 사용·관찰을 근거로 채우고 결과를 추측해 작성하지 않는다.

| 공식 배포처 시작점 | 찾을 수 있는 후보 예시 |
| --- | --- |
| [네이버 글꼴](https://hangeul.naver.com/font) | 나눔 계열, 마루 부리, 클로바 나눔손글씨. 각 폰트의 공식 샘플을 비교 |
| [Noto CJK 공식 저장소](https://github.com/notofonts/noto-cjk) 및 [Google Fonts Noto](https://fonts.google.com/noto/) | Sans/Serif의 한국어(KR) 버전과 필요한 굵기 |
| [Pretendard 공식 저장소](https://github.com/orioncactus/pretendard) | 고딕 계열의 한국어 버전·굵기별 후보 |

이 목록은 검색 출발점이며 원본과의 최적 대응을 보장하지 않는다. 배포 파일·라이선스·버전·페이지 경로는 작업 시 공식 출처에서 다시 확인한다. 폰트 모음 사이트나 블로그는 발견용으로 사용할 수 있지만 다운로드·권리 판단은 제작자 또는 공식 배포처를 근거로 한다.

## 다운로드와 로컬 검사

- 이 요청은 무료로 배포되고 사용 범위를 확인한 폰트를 작업 폴더에 받아 비교하는 흐름을 추가하는 요청이다. 실제 번역 작업에서는 필요한 후보의 TTF/OTF 또는 공식 ZIP을 `<work-dir>/fonts/<family>/`에 받는다. 일반 폰트 파일만으로 비교할 수 있으면 OS 전체 설치를 하지 않는다. 유료 구매·계정 생성·설치 프로그램 실행이 필요한 후보는 무료 대안을 먼저 검토하고 필요하면 별도로 사용자에게 알린다.
- 라이선스에서 해당 PDF/이미지 제작 용도와 사용자가 밝힌 사용 범위를 확인한다. 편집용 프로젝트를 타인에게 넘길 때 폰트 파일 재배포가 가능한지는 별도로 확인하고, 필요한 고지·라이선스 파일을 함께 보관한다. 무료라는 표시만으로 모든 권리를 가정하지 않는다. 패키지에 포함된 폰트를 확인하지 않은 채 스킬 자체에 묶어 배포하지 않는다.
- 공식 페이지에서 실제 다운로드 링크를 확인한다. 릴리스 버전과 URL을 추측하거나 최신 링크를 하드코딩하지 않는다. 원본 URL·버전/검색 날짜·폰트 파일 SHA256·라이선스 출처를 `<work-dir>/font-candidates.json` 또는 서식 메모에 남긴다.
- ZIP은 내부 경로를 확인해 작업 폴더 안으로 필요한 폰트와 라이선스만 추출한다. 브라우저가 받은 HTML을 `.ttf`로 저장한 경우를 걸러낸다. 웹폰트 WOFF/WOFF2와 한글 부분집합만 받아 전체 번역을 렌더링할 수 있다고 가정하지 않는다. ChiPDF가 사용할 수 있는 원본 TTF/OTF를 우선한다.
- `python <skill-dir>/scripts/font_inventory.py --font-dir <work-dir>/fonts --translations <translations.json> --output <work-dir>/font-inventory.json`으로 다운로드 후보도 검사한다. 이 도구는 기본 설치 폰트와 지정 폴더를 함께 수집하므로 `path`로 받은 후보를 구분한다. family/별칭과 실제 한국어·숫자·문장부호·한자 등의 지원을 확인한다. 전체 번역 검사에서 다른 역할의 기호 때문에 누락이 뜨면 해당 후보에 쓸 문장만 `--text`로 재검사한다.
- 정적 굵기별 파일을 우선 비교한다. 가변 폰트 축이나 같은 family의 Bold 선택이 JSON만으로 지정되지 않으면 실제 face 적용을 확인한다. 여러 버전의 같은 family를 한 프로세스에 함께 로드하여 원하는 버전이라고 가정하지 않는다. 다운로드가 불가능하면 웹 샘플 비교 상태로 남기고 로컬 적용이 완료됐다고 하지 않는다.

## 실제 번역문 비교와 최종 적용

1. [font-matching.md](font-matching.md)의 후보 비교 절차로 같은 대표 한국어 문장을 후보별 별도 JSON과 `.twproj`에 적용한다. 필요할 때 `python <script> --font-file <downloaded-font.ttf> apply <source.twproj> <candidate.json> --output <candidate.twproj> --no-fit`을 사용한다. 같은 source 프로젝트에서 시작하며 한 후보씩 필요한 파일을 로드한다.
2. 첫 비교에서는 같은 기준 크기·상자·정렬로 글꼴 외형을 확인한다. 다음 비교에서는 [layout-matching.md](layout-matching.md)에 따라 후보마다 실제 획 높이·폭·광학적 중심을 보정하여 원본과 비슷한 비중으로 맞춘다. 같은 숫자의 크기에서 작게 보이는 후보를 보정 없이 탈락시키거나 큰 후보를 무조건 선호하지 않는다.
3. 원본 crop과 후보 2~3개의 미리보기를 같은 배율로 나란히 열어 확인한다. 획 모양·굵기·자폭·밀도·제목의 분위기·본문 가독성·줄바꿈과 잘림을 비교한다. 모든 후보 이미지를 실제로 보기 전에는 최고 유사 후보를 선정했다고 하지 않는다. 로컬 폰트 후보가 있으면 비교에 함께 포함할 수 있다.
4. 역할별 선택 결과와 대안·선택 이유·남은 차이를 기록한다. 외형이 충분히 맞으면 에이전트가 선택해 진행한다. 후보 선택을 매번 사용자 승인 단계로 만들지 않는다. 사용자가 원하면 원본과 후보가 포함된 비교 이미지를 전달한다.
5. 최종 JSON의 `layout.font_family`와 보정한 크기·rect를 반영한다. **apply·preview·export 각각에** 다운로드한 파일을 `--font-file`로 전달하고, 재실행할 때도 해당 파일이 유지되어 있는지 확인한다. 파일을 로드했다고 실제 face가 맞다고 단정하지 말고 최종 렌더링을 확인한다. OS 미설치 폰트를 사용하는 `.twproj`는 편집기에서도 같은 폰트 로딩이 지원되는지 확인하고 필요하면 수동 마무리 안내에 적는다.

최종 전달에는 선택한 폰트와 공식 배포처, 주요 선택 이유 및 미해결 차이를 간단히 적는다. 이 기능은 에이전트의 웹 탐색과 시각 비교 흐름이며 `font_inventory.py`가 웹 검색·다운로드·이미지 유사도 계산까지 자동 수행하는 기능은 아니다.
