# 치pdf

PDF와 이미지 속 일본어를 인식하고, 한국어로 번역·편집하는 Windows 데스크톱 프로그램입니다.
문서 인식과 번역은 PC에서 처리하며, 원본 페이지 위에서 글자와 그림의 배치를 편집할 수 있습니다.
소스의 기본 번역 엔진은 Chrome 내장 번역입니다. 번역할 때 Chrome 보조 창에서 준비 버튼을 눌러 연결합니다.

## 주요 기능

- **문장 인식과 번역** — 원하는 문장을 사각형으로 선택해 일본어를 읽고 한국어로 번역합니다. 가로·세로 원문을 지원하며, 원문을 수정하거나 번역 후보를 비교해 적용할 수 있습니다.
- **텍스트 편집** — 글꼴, 크기, 색상, 부분 강조, 정렬과 문단 간격을 조절합니다. 한국어 세로쓰기와 글꼴 즐겨찾기도 지원합니다.
- **원문 지우기와 배경 복원** — 문장 영역이나 브러시로 지정한 원문을 지우고, 도장 도구로 주변 배경을 복제합니다. 원본 비교로 편집 전 모습을 볼 수 있습니다.
- **이미지·도형과 배치** — 이미지와 도형을 추가하고 크기·회전·자르기·뒤집기를 조절합니다. 정렬, 간격 맞춤, 그룹, 앞뒤 순서와 잠금 기능을 제공합니다.
- **PDF 페이지 링크** — 원본 PDF의 내부 페이지 링크를 번역문에 이어 붙이거나, 텍스트 상자에 이동할 페이지를 직접 지정합니다.
- **여러 페이지 작업** — PDF와 이미지를 함께 열고 페이지별로 편집합니다. 작업은 자동 저장되며, 원본과 편집 내용을 담은 `.twproj` 파일로 이어서 작업할 수 있습니다.
- **최근 작업** — 파일 메뉴의 `최근 작업 열기` 또는 시작 화면의 목록에서 최근 편집한 작업을 선택해 불러옵니다. 자동 저장본을 포함해 최대 12개를 보관하며, 파일 이름과 경로를 함께 표시합니다.
- **PDF·PNG 출력** — 전체·현재·선택한 페이지를 저장합니다. PDF에는 편집된 페이지 이미지와 내부 페이지 링크가 포함됩니다.

Windows 10 1809 이상·Windows 11의 64비트(x64) 환경을 지원합니다.

## 0.11.3 편집기 개선

- 글자 크기 등 숫자 입력칸의 위·아래 화살표를 명시적인 아이콘으로 표시하고, 값과 단위가 잘리지 않도록 조정했습니다.
- 파일 메뉴와 시작 화면에서 최근 작업을 선택해 불러올 수 있습니다. 자동 저장본을 포함해 최대 12개를 기억하고, 기존 마지막 작업 기록도 이어받습니다.
- 배경 복원의 `이전 방식` 이름을 `주변색 보간`으로 바꿨습니다.
- 작은 창에서도 시작 화면을 스크롤해 최근 작업 목록을 사용할 수 있습니다.

변경 내용과 검증 범위는 [0.11.3 릴리스 노트](docs/releases/0.11.3.md)를 참고하세요.

## 글씨 지우기와 사진 복원

`번역·지우기 → 브러시`에서 `글자만 선택` 또는 `칠한 부분 전체`를 고릅니다. 글자만 선택할 때는 사진의 글자를 **Alt+클릭**해 색을 고른 뒤 주변을 칠하세요. **Shift+드래그**는 선택을 뺍니다. 한 획을 마치면 빨간 표시가 실제로 지울 픽셀만 보여 줍니다. `지우기 설정`에서 글자색, 비슷한 색 포함 범위, 테두리 확장을 조절할 수 있습니다.

복원 방식은 `주변색 보간`(예전 사진 편집기의 주변색 보간·32회 평활화)과 `사진 복원 · LaMa`입니다. `지우기`를 누르면 현재 배경의 선택 영역만 바뀌며 기존 되돌리기·저장 기능을 사용합니다. 두 방식을 비교하려면 지운 직후 Ctrl+Z로 되돌린 뒤 같은 영역을 선택해 다른 방식을 적용하세요. PDF 원래 배경 자산을 사용할 수 있는 선택은 그 배경을 우선 사용합니다.

LaMa 배포판에는 모델과 실행 모듈이 포함되어 있어 별도 다운로드 없이 사용할 수 있습니다. 소스 실행 환경에서는 다음을 한 번 준비합니다. 기존 개발용 Python을 사용하세요.

```powershell
python -m pip install --target .deps -r requirements-inpaint.txt
python prepare_inpaint.py --download
python main.py
```

이미 모델을 받았다면 `python prepare_inpaint.py --from-file "C:\path\lama_fp32.onnx"`로 검증·복사하거나 `지우기 설정 → 파일 선택`으로 연결할 수 있습니다. 모델은 고정된 Carve/LaMa-ONNX FP32 512×512 배포본(208,044,816바이트)이며 크기와 SHA256을 확인합니다. 추론 중에는 다운로드나 외부 API 호출을 하지 않습니다. 모델 또는 실행 모듈이 없으면 이유를 표시하고 선택을 유지하며, 다른 엔진으로 자동 전환하지 않습니다.

LaMa를 포함한 실행 파일은 `python build_portable.py --with-inpaint`로 빌드합니다. 기본 경량 빌드는 LaMa 모델·ONNX Runtime을 제외하므로 모델 파일만 연결해서는 LaMa를 실행할 수 없습니다. 사용자 설정은 앱 데이터 폴더의 `brush-settings.json`에 저장됩니다.

사진 전체를 512픽셀로 축소하지 않고 원본 해상도의 부분 이미지를 겹쳐 처리합니다. 가려진 배경은 추정 결과이므로 사진과 선택 영역에 따라 복원 품질이 달라집니다.

## 소스 및 배포 관리

앱 소스, 테스트, UI 아이콘, 빌드 스크립트와 외부 구성 요소의 라이선스를 이 저장소에서 관리합니다. 설치 파일·ZIP·모델·로컬 작업 데이터는 Git에서 제외하며, 배포 파일은 [GitHub 릴리스](https://github.com/chan0o0seo/CHIPDF/releases)에 첨부합니다. 각 릴리스의 태그는 해당 버전의 소스를 가리킵니다.

Windows용 Python 3.12 환경에서 `python -m pip install --target .deps -r requirements-dev.txt`로 개발 의존성을 설치하고 `python prepare_assets.py`로 OCR 자료를 준비한 뒤 `python main.py`로 실행합니다. LaMa를 포함할 때는 위의 추가 런타임·모델 준비 절차를 먼저 실행하세요.

`python build_portable.py --with-inpaint`로 이동식 배포본을 만들고 `python build_installer.py`로 같은 버전의 설치 파일을 만듭니다. `Start Translation Studio.cmd`는 `dist`의 가장 최근 앱 빌드를 실행하므로 저장소에 개인별 빌드 경로를 기록하지 않습니다.

## 0.11.0 경량 배포와 선택 오프라인 팩

기본 배포는 약 1.25GB의 M2M100 가중치를 포함하지 않습니다. Chrome 번역을 사용하는 경우 기본 앱만 받으면 됩니다. Chrome 설치와 첫 언어팩 다운로드 용량은 별도입니다. 작은 오프라인 추론 라이브러리는 앱에 남겨 두어, 필요할 때 데이터 팩만 추가할 수 있습니다.

- 오프라인 번역이 필요하면 별도 `ChiPDF-M2M100-1.2B-Offline-Pack.zip`을 받은 뒤 `번역·지우기 → 오프라인 팩 → 오프라인 팩 설치`를 선택합니다.
- 이미 모델이 있다면 `기존 모델 폴더 연결`에서 `model.bin`과 `origin.json`이 들어 있는 폴더를 고릅니다. 이전 앱의 `_internal/vendor/m2m100-1.2b-int8`도 연결할 수 있으며 모델을 복사하지 않습니다.
- 설치한 팩은 `%LOCALAPPDATA%/TranslationStudio/offline-models`에 보관하고, 연결 정보는 같은 사용자 데이터 위치의 `offline-model.json`에 저장합니다. 앱 업데이트와 독립적으로 유지됩니다.
- 모델이 준비되면 `번역 설정·용어집`에서 오프라인 엔진을 선택하세요. Chrome를 다시 선택하면 앱이 로드했던 오프라인 모델을 해제합니다.
- 기본 배포에는 팩이 없지만, 기존 설치 위치에 있던 모델을 업데이트 중 자동 삭제하지 않습니다. 기존 모델 폴더를 외부에서 연결한 경우 그 폴더를 이동하거나 삭제하면 다시 연결해야 합니다.

개발용 생성 명령은 `python build_portable.py`(기본 경량판), `python build_model_pack.py`(별도 데이터 팩), `python build_installer.py`(설치 파일)입니다. 예전처럼 모델까지 묶으려면 `python build_portable.py --with-offline-model`을 사용합니다. 기본 자료 준비 명령 `python prepare_assets.py`는 번역 모델을 요구하지 않으며, 모델 출처 자료까지 갱신할 때만 `--offline-model`을 붙입니다.

0.11.0 설치 파일은 약 108MB, 이동식 ZIP은 약 123MB이며 압축을 풀면 약 330MB입니다. 선택 오프라인 팩은 약 1.17GB입니다. 배포 파일은 [GitHub 릴리스](https://github.com/chan0o0seo/CHIPDF/releases)에서 받을 수 있습니다.

## 번역 사용 방법

1. `번역·지우기 → 번역 설정·용어집`에서 Chrome 내장 번역 또는 기존 오프라인 엔진을 선택합니다. 설정은 작품마다 저장됩니다.
2. Chrome 엔진으로 번역을 누르면 번역 도우미가 열립니다. 도우미에서 `번역 준비`를 누르세요. 처음에는 Chrome가 일본어·한국어 언어팩을 준비합니다.
3. 도우미를 열어 둔 채 치pdf에서 문장을 번역합니다. 연결이 끊기면 `Chrome 연결`로 다시 열고 준비한 뒤 남은 문장을 번역하세요. 기존 번역문은 기본적으로 건너뜁니다.
4. 원문·번역 패널의 `화자·문맥·문단 입력`에서 줄 연결을 끄거나 번역에 사용할 입력을 확인할 수 있습니다. 다른 상자의 글은 자동으로 합치지 않습니다.
5. 작품 용어집에 권장 표기와 피할 표기를 등록하면 결과의 표기 문제를 표시합니다. `용어 표기 제안`은 교체 결과를 후보로 제시하므로 뜻·조사를 확인한 뒤 적용하세요.
6. `검토 완료`한 문장은 작품의 확정 번역에 저장됩니다. 같은 원문·화자·문맥에 재사용하고, 유사 원문은 `확정 번역에서 찾기`로 선택합니다. `다시 번역해 비교`는 재사용을 건너뛰고 새 번역을 요청합니다.

새로 가져온 PDF의 선택 가능한 텍스트를 작업 파일에 함께 보관합니다. 새 원문 영역을 읽을 때 해당 텍스트를 우선 활용하고, 불완전한 텍스트나 이미지 부분은 OCR로 처리합니다. 기존 프로젝트는 `PDF 원래 배경 적용`으로 원본 PDF를 다시 연결하면 일치하는 페이지의 텍스트 정보도 보관합니다. 직접 수정한 기존 원문을 자동으로 바꾸지 않습니다.

원문·번역 패널에서 원문 출처, 번역 출처, 숫자·용어·반복·일본어 잔존 등의 확인 안내를 제공합니다. 안내가 없더라도 번역 정확성을 보장하지 않습니다.

이 소스는 작업 형식 10으로 저장하며 이전 형식 1~9를 읽습니다. 새로 저장한 형식 10 파일은 이전 실행 파일에서 열리지 않을 수 있으므로 기존 저장본·백업을 보관하세요.

0.11.0 배포 파일은 테스트·앱 실행·표본 번역 없이 빌드했습니다. 번역 품질과 설치·실행 동작에 대한 별도 검증은 수행하지 않았습니다.
